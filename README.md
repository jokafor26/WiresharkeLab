# WiresharkeLab

Wireshark Project

Wireshark is an open source traffic network monitor. Using the interfaces of the device that is being used for networking Wireshark is able to track traffic going between the network to and away from the network device. Wireshark could traffic or scan the networks through Ip’s or through protocols. we could see how data is being transferred through the network by setting to listen(track/scan) the network through the network card then we can’t see how that information is being tracked, and then maybe hackers or people listening could see which kind of protocol is being used between the devices then we could scan the information which is the critical part of the packet(data).
for the project we had to monitor 2 virtual machines with Linux installed and track traffic flow between them through any protocol like FTP (file transfer protocol) or Telnet. so, using VirtualBox I created a new virtual machine from scratch like Lab 1. I decided not to clone the previous machine but instead making it from scratch. cloning a virtual machine will result in the machine have the same network information and MAC address (Media Access Control) although there’s an option to re initialize it, but to stay safe I decided to make a new machine. using the same steps as lab 1 I got the iso for Ubuntu and loaded it onto VirtualBox and made a new Ubuntu virtual machine.
with my machine set up I downloaded the Wireshark program from the Wireshark website and installed it on my host system. Wireshark comes with Pcap (packet capture) which is required in order to capture packets which going are growing across the network. also, Wireshark could traffic usb traffic which is USB Pcap will also be installed but is not necessary for this project. with Wireshark setup we could see the interfaces on the device and see other interfaces as well, and this will be used to actually traffic the flow of packets between the two virtual machines.
now back to virtual machines I wanted to use ftp which transfers packets through port 20 & 21 then monitor traffic through Wireshark but ran into some connection errors and could not communicate between machines. so, with my machines not being able to connect to each other Wireshark would not be able to scan traffic between them. So I switched and used telnet which uses port 23. telnet isn’t secure much so it will be the perfect way to monitor what’s going on, so on my Linux machines I had to download and install telnet. on the command line I used the command ‘sudo apt-get install telnet’. this command downloads telnet server, and installs it onto my Ubuntu machines. 
With telnet installed I had to edit some configurations within the file to get it working the way I wanted it to. by using an editor of my choice which was VIM I used the command ‘vi /etc./intended’ this will open the Netconf file which is in the etc. folder which is in charge of keeping configurations for the system. I added lines like ‘disable = no, user = root, flag = REUSE’ and others to have the configuration set, and then saved it and names it telnets which is located in the /etc./intended/telnet directory. with the file created I know how to restart the telnet service using the command ‘sudo service hinted restart’, so now the server will be restarted with the configuration files all set and ready to be used.
to use telnet the command will be as follows ‘telnet _____ (Ip address of the system you want to log into)’ then telnet will try to connect to the server of the other device. once logged in you will now be able to see the files on the device, make files and do other telnet related services. my 2 virtual machines are called ‘alpha’ & ‘omega’, so using alpha ill connect to omega using the command ‘telnet 10.36.206.224’ this will prompt me to login with a name and the password for the omega system. Now I am in the system of omega through the telnet connection I could monitor activities through Wireshark.
with Wireshark opened I selected the network device which my 2 virtual machines are connected to which is a ‘en0’ & is connected with a bridge adapter in the VirtualBox network settings
